## GPUI 鸿蒙 PC 可用性评估（同日，用户提问）

- 结论：GPUI 官方仅 macOS/Windows/Linux，不支持鸿蒙；鸿蒙 PC 硬门槛 = musl libc + 强制签名 + 无 Wayland/X11。
- 社区方案 ohos-rs/gpui-template 已把 GPUI 适配 OpenHarmony（GLES 后端、替换 SSBO shader、复用 winit 事件归一化），作者跑通两个较复杂 App，但属早期、需自行维护 fork。
- 播放内核在鸿蒙更难：rodio/cpal OHOS 支持不确定，libmpv 基本不可行，需换 OH Audio/AVPlayer + XComponent。
- 项目决策：主线按 gpui-kit 走 Win/macOS/Linux 三端；鸿蒙端若做，走 clashmi 同款 ArkTS UI + Rust 核心路线，不单列进本计划。

**技术选型改道（重要）**：放弃 libmpv 纹理共享/软解帧，改为 **mpv.exe 子进程 + `--wid` 顶层叠加窗口 + JSON IPC**。
- 根因：GPUI Windows 后端用 DirectComposition + WS_EX_NOREDIRECTIONBITMAP，**无法承载原生子窗口**，"嵌入渲染到 GPUI 窗口"这条路在 Windows 上不通。
- 方案：`CreateWindowExW(WS_POPUP|WS_CLIPCHILDREN|WS_CLIPSIBLINGS, WS_EX_TOOLWINDOW|WS_EX_NOACTIVATE, owner=主窗口)` → mpv `--wid=<该 hwnd>`，
  `vo=gpu` + `hwdec=auto-safe` 直接硬解上屏，零拷贝。代价：视频区内的 GPUI 元素被遮挡。
- 先做可行性探针（scripts/probe_mpv_wid.py）再写代码：testsrc 彩条占 76.56% 彩色像素 → 确认可行。

**Windows 命名管道死锁（核心坑，花了大半天）**：
- 症状：`pause` 之后再发任何命令永久卡死；单测整片挂起（exit 143），诊断例程显示卡在 pause 之后的 sleep。
- 根因：**同一命名管道连接上，挂起的 `ReadFile` 会阻塞 `WriteFile`**（即使 try_clone 出来的句柄也序列化）。
  pause 后 mpv 不再发事件 → 阻塞读一直挂着 → 后续写全部排队 → 死锁。
- 解法：单线程串行 IPC worker —— 先排空 mpsc 命令队列（此刻必无挂起读）→ `PeekNamedPipe` 探测可读字节 → 有数据才 read，否则 sleep 10ms。
  实测 resume+seek+volume 三连下发 10.6µs，shutdown 90.69ms。

**新增文件**：
- `crates/player-core/src/video.rs`：VideoEngine（spawn/load/pause/resume/seek/set_volume/stop/status/is_connected）、VideoStatus、find_mpv（SMP_MPV_PATH → PATH → choco/Program Files）、is_video_file（15 种容器）、ipc_worker + pipe_available(PeekNamedPipe FFI)。
- `crates/app/src/video_overlay.rs`：纯 FFI 顶层叠加窗口（无新 crate），set_rect/show/hide/Drop=destroy、client_origin(ClientToScreen)；坐标 = 客户区原点 + 逻辑坐标×scale_factor。
- `crates/app/src/player_view.rs`：VideoRuntime{overlay,engine} + video_active/video_error/video_rect(Rc<Cell>) + main_hwnd（raw-window-handle 取 HWND）；
  cx.observe_window_bounds → sync_overlay_rect；cx.on_app_quit → shutdown_video；canvas(prepaint) 捕获视频区 → 叠加窗口 SetWindowPos 跟随。

**M2 期间发现并修掉的两个真缺陷**：
1. 影院模式下视频播完自动连播切到音频后 `cinema` 未复位 → 影院按钮消失、用户被困全屏。修：tick 里 `cinema && !video_active` 时主动退出全屏。
2. 全屏时退出应用会把 3840×2160 当窗口尺寸落盘 → 下次启动开成全屏大小。修：cinema 期间跳过尺寸落盘。

**验证方法沉淀（比 M1 进步）**：
- M1 教训是"屏幕坐标点击会点到别的应用"，M2 用 **临时置顶 + 窗口归位** 解决：截图/点击前 `SetWindowPos(hwnd, HWND_TOPMOST)`（主窗口和叠加窗口都要），
  `place_window(0,0)` 让截图像素与窗口坐标 1:1，做完立刻 `HWND_NOTOPMOST`。**注意必须给 SetWindowPos 设 argtypes，否则 64 位下 HWND_TOPMOST(-1) 被截断成 0xFFFFFFFF，静默失败。**
