### 26.2 本轮改的三处

1. **次要文字色**：`overlay::dim()` 是 `#8B909C`，spec 是 `tokens.osc.text_secondary
   = #A6ADC8`（原型 `.times .remain` 同值）。红/黄彩条上剩余时间几乎读不出 →
   改成 `#A6ADC8`，并删掉同值的 `overlay::label()`（两处合成一处）。
2. **性能用例偶发红**：`liquid_glass::tests::capsule_on_a_720p…` 的三面烘焙是墙钟
   断言（< 90ms），并行跑测试时实测 65ms ↔ 116ms。改成**取 3 次最小值**（改胶囊 x
   强制重烤，不 sleep），阈值不动。
3. **验收脚本的 ⓘ 判据**：卡片在 L4 之后是**自适应压暗**（渐变，顶部几乎不压、
   底部到 scrim 上限），原来「三通道和掉 80」是按 L3 的 72% 平压定的 → 卡片画对了
   也判 FAIL。改成取**卡片底部 padding** 那一点 + **相对比例 < 0.80**（实测画出 0.58、
   没画 1.0）。同时在信息卡阶段前把窗口重新停到 (0,0)：前面拖过窗体、进过全屏，
   窗口可能被摆到屏幕边缘之外，`ImageGrab` 对越界 bbox 是裁剪语义，图会多一条黑边、
   整幅内容右移，卡片坐标就落偏了。

### 26.3 环境坑（这次排查花了不少时间）

## 26. 玻璃面圆角（用户：「控制栏的圆角有明显问题」）

现象：胶囊四角是**硬切阶梯**，且顶边那条 1px 亮线在进圆角处突然断掉、弧上只剩一圈暗边。

两个独立原因：

1. `render_plate` 在贴图里按 SDF 二值裁圆角（`d > 0` → alpha 0 + RGB 清 0）。贴图是
   `PLATE_SCALE = 0.5` 再拉到物理像素（1.5× DPI ⇒ 放大 3×），双线性插值把
   「边缘色 → 纯黑」糊成 2~3 物理像素的灰黑毛边；弧线本身也是 3× 放大的硬切阶梯。
2. 描边 `border_1()` 挂在根节点上，而 GPUI 的 border 先于子节点绘制 → 被整幅玻璃贴图
   完全盖掉。用户看到的"边"其实是贴图里的 rim，所以圆角处没有白色描边。

改法：

- `render_plate` 不再裁圆角：`d` 夹到 0（沿用边缘色）、alpha 恒 255、输出整块矩形；
  圆角交给外层 `rounded + overflow_hidden`（矢量、1:1 物理像素、自带 AA）。
- 描边改成 `.absolute().size_full().rounded(r).border_1()` 的覆盖层，压在贴图之上；
  胶囊 / 信息卡 / 歌单面板三块面统一。
- 液态玻璃不再画顶亮/底暗那两条 1px 直条（进圆角会被裁断），只留整圈 border；
  非液态（音频模式）保持原样。顺手删掉 `liquid_highlight` / `liquid_light_highlight` /
  `liquid_light_shade` 三个色函数。
- 去掉根节点 `border_1()` 后内容盒宽了 2px → `PROGRESS_SIDE_PAD` 2 → 3（回到设计稿），
  否则 `capsule_is_760_by_92...` 断言轨道 714 会红（实测 716）。

验证：`cargo test --workspace` 29 + 51 全绿；`verify_floating_chrome.py` **18 项 ALL OK**
（多了「视频模式整窗圆角」一条）。

## 第十七轮：圆角液态玻璃（分辨率，不是裁切方式）

用户追问「无法做到圆角液态玻璃吗」——上一轮的修法只是把毛边换成了阶梯，弧线本身还是糊的。

真正的根因：贴图按 `PLATE_SCALE = 0.5` **逻辑像素**烤，1.5× DPI 下等于放大 3 倍。
胶囊圆角半径 14、折射带 14 → 贴图里只有 7 个像素，弧长方向才 11 个采样点。设计稿的
HTML 原型一直是 `canvas = W × devicePixelRatio`（1:1 物理像素），Rust 这边从第一版就低一档。

改法：

- `plate_scale(job, dpi)`：目标 `window.scale_factor()`（封顶 2.0），单块面 **22 万像素**封顶，
  超了按面积降。暗底（胶囊 / 信息卡）在 150% 下就是 1:1（1140×138）；浅底歌单乘 0.72 再降。
- 圆角改回**贴图内裁**，但用**物理 1 像素**的 alpha 覆盖率：
  `cover = clamp(0.5 − d_raw·dpi, 0, 1)`。过渡带宽与贴图分辨率解耦，二值裁切那套灰黑毛边
  不会再出现；外层 `overflow_hidden` 留作双保险。
- `sync` 多一个 `dpi` 参数，`BakeKey` 记 `dpi_q`（×64 定点），换显示器会重烤。
- 内层循环按行/列预计算 SDF 的 `qx`/`qy`、采样基准坐标和暗底压暗的仿射系数
  （`qx` 只跟 x、`qy` 只跟 y），`sample` 展开三通道 + `#[inline(always)]`：
  三块面 17.9 → 14.5ms（release），胶囊 4.9ms。
- `BAKE_MIN_INTERVAL` 从「debug 90ms / release 0」改成**统一 20ms**：贴图像素数 ×9，
  每帧重烤吃满预算，而玻璃里装的是模糊倒影，慢一两帧看不出来。布局变化不节流。
- `[profile.dev/testing.package.*] opt-level = 2`：液态玻璃在 opt-level=0 下慢一个数量级，
  debug 窗口会卡成幻灯片。依赖仍用 0（它们慢在启动，不在每帧）。

验证：`cargo test --workspace` 29 + 51 全绿；`verify_floating_chrome.py` **18 项 ALL OK**；
物理像素四角 8× 放大（`target/round-phys.png`）弧线连续，只剩 1 物理像素的边缘过渡。
