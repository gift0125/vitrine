## 1. 控制层退场：标题向上收走，胶囊散成尘

用户提：**控制栏消失时做鸿蒙的粒子效果，标题栏消失时有个向上的动画。**

### 1.1 决定（两条动作分开做）

| 谁 | 怎么退 | 为什么 |
|---|---|---|
| 标题带 | `translateY(-12px)` + 淡出，`.36s cubic-bezier(.22,.78,.28,1)`；traffic `-7px` | 它是**信息** |
| 顶部压暗 | `.42s` 一并淡掉 | 本来只为托住标题，标题走了就没有存在理由 |
| 控制胶囊 | **散成尘**：本体 `.18s` 淡出，形体交给 340 颗粒子 | 它是**材质** |
| 回场 | 聚 520ms 先走，胶囊 `.26s` + `.07s` 延迟淡入 | 聚是"响应"不该让用户等；且要在淡入完成前成形，否则像被擦掉 |

方向统一（向外 + 向上），读者才觉得是"一起退场"。

**不做「滑出窗口」**：标题贴顶边 25px，滑出去要 25px+，位移太大像抽屉，而且文字会在窗口
边缘被切一半。-12px 足够读出方向。

### 1.2 粒子参数（`DUST`）

- 340 颗；只在 **12px 轮廓带**取点，按 `exp(d/5.04)` 拒绝采样（d = 圆角矩形 SDF）
- 沿 **SDF 梯度**（= 外法线）外推 `24 × (0.45~1.0)`，叠浮力 `16·e²`，再加切向 `sin(u·5+φ)`
- 散 `1-(1-u)³` / 聚 `(1-u)²`；alpha `.55 × (1-u)^1.5`；半径 0.4~1.6，三档混合
- `lighter` 混合；32×32 径向渐变 sprite 逐帧 `drawImage`

### 1.3 这轮真正踩到的三条

- **别用 `arc` 填圆画粒子**：硬边读成噪点。但也**别逐帧建渐变**（60fps 直接垮）——
  预渲染一张 sprite 再 `drawImage` 拉大小。
- **粒子密度必须按轮廓带加权**。第一版均匀撒，看着像满屏星点，读不出"是那根条在散"。
  修法两层：贴边权重量级远大于内部 + `delay` 随贴边程度走（边先松、中心最后走）。
- **headless 的 `--virtual-time-budget` 不推进 CSS transition**（只推进 `setTimeout`）：
  `getComputedStyle` 永远读到起始值；而 `?bare=1` 又带 `transition:none!important`。
  所以动效只能靠**端点态截图 + `transitionProperty/Duration` 读数**验证，别指望截到中间帧。
  （粒子能截，是因为 `?dust=` 是同步算好一帧直接画。）

另外：canvas 在 `fit()` 缩放下跟着缩，整页截图里 1px 粒子会缩没——要看 1:1 就 `?bare=1`。

### 1.4 产物

- `design/preview/index.html`：CSS 两条动作 + `.dissolve` canvas + `DUST` 模块 + `?dust=` 冻结相位
- `design/spec.json`：`chrome_auto_hide.motion`
- `design/README.md`：闲置淡出小节改成「谁 / 怎么退 / 为什么」表
- `docs/chrome-dissolve.png`（五条横带）+ `scripts/make-chrome-motion-doc.py`

## 2. 澄清：粒子走不走 render API

用户问「现在不是 render api 去做吗」——针对我上一轮「粒子得自己写一套粒子模拟 + 每帧重绘制」
这句。**这句把话说拧了**：说成像要另造一层渲染。

### 2.1 render API 到底给了什么

给的是**视频帧像素**（sw → BGRA），不是「画 UI 的能力」。胶囊 / 文字 / 按钮仍是 GPUI 矢量节点，
不在 mpv 帧里。所以：

- **玻璃必须 ingest**（要模糊背后的画面）；
- **粒子不需要 ingest**（像素自己生成），但它能搭同一条上屏通道。

真正通用的是后半段 `BGRA → RenderImage → img()`，和视频无关。现有实现：
`ingest → sync(win_w,win_h,jobs,hue,dpi) → plates() → render_image() → img() → drop_image`，
`RETIRED_KEEP=8`。

### 2.2 为什么必须烘进同一张 Plate（而不是 GPUI 画节点）

**加色混合（lighter）在 GPUI 层叠里没有逐节点入口**，在 BGRA 里就是一次饱和加法。
这是决定性理由；顺带省掉 340 个节点的布局与绘制。

### 2.3 不需要双通道

粒子与玻璃时间上几乎不重叠：退场时胶囊 .18s 就淡出、粒子接管；回场时粒子在聚、玻璃直接用缓存。
同一张贴图分时复用即可。

### 2.4 要改三处

1. `GlassJob` 加相位（几何已在 job 里）；
2. **`bake_key`/`JobKey` 必须把相位量化进去** —— 现在只含
   `generation | win_w/h | hue | dpi | 三个 (x,y,w,h)`，相位变了会被判「没变」直接
   `return false`，粒子一帧都不会重画。这是最容易漏的一条；
3. 粒子在跑时绕过 `BAKE_MIN_INTERVAL`（=20ms，不是记忆里的 90/0，已被并行会话改过）——
   那节流是防整帧烘焙拖垮 UI，而粒子期间玻璃 pass 走缓存，成本降到约 1/40。

### 2.5 成本与风险

- 胶囊 plate 28 万 px @2x；一次玻璃 bake ≈ 50 万次双线性采样。
- 粒子 pass 每帧 ~1.2 万 px 写入（340 × ~36px sprite）= 玻璃的 1/40，且跳过玻璃重算。
- 上传 1.1MB/帧；50fps × 640ms ≈ 32 帧。
- **风险**：`plates()` → `to_vec()` 每帧新分配 1.1MB 堆内存，32 帧连续烘焙要看有没有分配抖动，
  必要时复用 buffer。
- **不做**「预生成帧序列按时间轴重放」：几何一变全废，而现算便宜得多。

`spec.json → chrome_auto_hide.motion.rust_landing` 已记全（pipeline / why_bake_into_plate /
needs_three_edits / cost / open_risk / not_doing）。

## 3. 按新 spec 落地：粒子烘进 GlassPlate（Rust 侧实现）

用户：**按新的 spec 实现**——`design/spec.json → chrome_auto_hide.motion.rust_landing`
把接入路径定死了，上一轮我写的独立 `dust.rs` 贴图图层要作废。

### 3.1 架构

`dust.rs` 删掉，粒子搬进 `liquid_glass.rs`，做成**同一张 plate 的第二道 pass**：

- `GlassJob.dust: Option<DustPhase { u, scatter, fade, run }>`；几何/圆角本来就在 job 里。
- 带光尘的 plate 四周多留 `DUST_PAD = 48`（外推 24 + 浮力 16 + 光点半径），
  `render_plate` 多一个 `pad` 参数，胶囊本体从 `(pad, pad)` 开始写，留边保持透明。
- 粒子的坐标/半径乘 `scale`（贴图是物理像素），撒点照旧用圆角矩形 SDF + 软权重。
- **加光用预乘空间的屏幕混合**：`na = a0 + (1-a0)·k`、`c = (c·a0 + 255k)/na`。
  透明处得到「白 + 覆盖率」，不透明处得到「原来的颜色往白推」——单张 source-over
  贴图里能做到的最接近 `lighter` 的东西。
- `fade`（胶囊本体 alpha）烘进贴图：贴图挂在根节点上、不在控制层的 opacity 下面，
  否则粒子会跟着胶囊一起消失。

### 3.2 三条必须做的（spec 点名，也确实是坑）

1. `bake_key`/`JobKey` 把相位量化进去（`u` ×65534、`fade` ×255、`scatter`、`run`）
   ——不写这条，几何/帧/色相都没变，`sync` 判「没变」直接返回，粒子一帧都不动。
2. 粒子期间绕过 `BAKE_MIN_INTERVAL`（20ms）。
3. 玻璃 pass 走缓存（`DustBase`，`DUST_BASE_REFRESH = 120ms`）：实测首帧 4.68ms、
   缓存帧 0.23ms（release 同口径）。缓存没有每帧失效，是因为退场时胶囊 0.18s 就淡完，
   镜头糊在玻璃里看不出来；回场也只有 0.26s。

### 3.3 界面侧

- `ChromeRun` 带三条腿：胶囊（`.18s` + 70ms 延迟，回来 `.26s` + 70ms）、标题带
  （淡 `.22s` / 位移 `.36s`、-12px）、顶部压暗（`.42s`）。16ms 帧循环推进。
- 标题带拆开：文字走满 12px、**窗口按钮只走 7px**（设计稿），所以位移挂在元素上而不是整条上。
- 顶部压暗从 `render_title_band` 里搬出来做独立一层：它比标题慢 0.2s，套在同一个
  opacity 里就分不开了。
- 胶囊淡出时沉 3px（`CAPSULE_SINK`）；设计稿还有 `scale(.985)`，gpui-pre 没有 transform，
  1.5% 本来也看不出。
- 光尘那层贴在**根节点**上（胶囊 ± 48px），压在胶囊内容下面——塞进胶囊 div 会被
  `overflow_hidden` 切掉飞出去的尘，套着的 opacity 又会让它跟着胶囊消失。

### 3.4 验证

- `cargo test --workspace`：29 + 59 全绿（新增 8 条：撒点只在轮廓带、相位进 key、
  留边尺寸、粒子确实烘在同一张图、fade 烘进 alpha、sprite 剖面、缓存后便宜、相位预览图）。
- `scripts/verify_floating_chrome.py`：**18 项 ALL OK**。
- 截图：`target/fade/out-06.png`（散到一半，胶囊淡出 + 轮廓起尘）、
  `target/dust-plate-{0..3}.png`（相位 0.12/0.28/0.45/0.62 的贴图形态）。
- 踩坑：窗口被浏览器盖住时整屏截图会拍到浏览器，脚本要先 `SetWindowPos(HWND_TOPMOST)`
  且**给 `SetWindowPos` 设 argtypes**（不设时传 -1 会被截断，返回 0 失败）；
  `PrintWindow` 抓 D3D 交换链拿到的是过期帧，别用。

## 3. 消散方向改成「从左至右」，顺手挖出冻结 bug

用户：harmony os 7 的粒子是从左至右的，能做吗。原版是「沿 SDF 法线向四周外推 + 浮力上飘」，
方向感是散的。

### 3.1 关键判断：方向靠**延迟**，不靠位移

只把位移改成 +X，看到的是「整块往右平移」，没有「扫过」的过程。真正建立方向的是
`delay = 0.55×xn + 0.07×(1-near) + 0~0.10 随机`：左边先散、右边最后，一道锋面扫过去。

### 3.2 踩到的坑：带宽不能随 x 变

第一版想让「迎风面整列被剥」，把左端 band 放大到 3.2×（左端几乎整条高度都取点）。
但**采样密度同时被放大了**：左端通过率 45%、右端 9%。结果左边一堆先散、右边稀稀拉拉，
读成「一团浓雾向右淡去」。方向只该由时间差表达，每列粒子数必须一样 —— 这是本轮最重要一条。

### 3.3 冻结 bug（`?dust=` 一直是假的）

```js
motesT0 = performance.now() - freeze * motesDur;
motesFrame(motesT0);        // u = (motesT0 - motesT0)/dur = 0，恒为 0
```
而且 rAF 不停，实际相位 = freeze + 截图前的若干 ms。所以：
- 靠后的相位（0.74/0.88）被冲过终点、整块清空
- 之前 docs/chrome-dissolve.png 的相位标注全是不准的

现在：`motesFrame(motesT0 + freeze*dur)` 让 u 直接落在 freeze，且 `motesFrozen` 提前 return。

### 3.4 两个新诊断参数（以后做粒子/动效都用得上）

- `?seed=<n>`：固定粒子种子。**静态截图看不出运动方向**，只有「同一批粒子在两个相位的
  位置差」才说明问题。固定后同相位两次截图逐字节一致（实测 diff sum = 0）。
- `?dusthold=1`：胶囊停半透明。否则 idle 一上来胶囊淡到 0，粒子浮在背景上，
  看不出是从哪块形体散的。

### 3.5 参数加强（原来太弱，退场几乎看不见）

| | 旧 | 新 | 原因 |
|---|---|---|---|
| count | 340 | 400 | |
| band | 12 | 13 | |
| push | 24 | 48 | 24 太贴边，读不出被吹走 |
| alpha | 0.55 | 0.72 | 暗画面上 3~5px 的点几乎看不见 |
| 散曲线 | ×(1-u)^1.5 | ×(1-u²) | 衰减太快，640ms 里只可见前 200ms |
| rise | 16 | 5 | 16 是「四周散」的浮力 |

### 3.6 量化验证（seed=7，逐相位差分 + 列统计）

锋面档每行的「左沿」与「x 质心」都单调后移：

front `0.10→0.62` 强锋面 / side `0.08→0.22` 弱锋面靠位移 / out 平坦 `≈0.15` 无方向。
