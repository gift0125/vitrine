设计稿是**云端 Ardot 文件**（`ardot.tencent.com/file/737444551354649`），仓库里没有、也不会有 `.ardot`。

### 为什么视频态不在画布上

2026-10-18 删掉了 6 个视频帧（主窗 / 歌单展开 / 视频信息 ×2 平台，共 668 个节点），它们和 HTML 原型是同一件事的两份拷贝，而且改一次质感要同步 6 个帧（上一轮 L3 就漏改过 2 个 OSD 帧）。

现在**视频播放态只有 HTML 原型一份**：真模糊、闲置淡出、交互都只有它能表达，静态帧本来也画不出来。画布上原位换了一块「占位 · 视频播放态」说明板指过去。

需要重建的话，结构快照在 `archive/video-frames-2026-10-18.jsonl`（逐节点 JSON，含完整子树）。副作用：`spec.json → texture_layers` 的 L3 参数现在是唯一文字定义处，`docs/capsule-compare.png` 变成历史对照（它的「画布」那一半取自已删的帧，无法重生成）。

## 控制栏质感：已定稿 L3

控制栏不是一块「半透明黑」。它分四层，按依赖顺序叠加（精确参数见 `spec.json` → `texture_layers`）：

| 层 | 做什么 | 实现代价 |
|---|---|---|
| **L1 方向光** | 顶部高光 + 底部暗线 + 双段投影 + 画面底部 vignette + hover 响应 + 等宽数字 | 纯样式，**现在就能做** |
| **L2 画面染色** | 从画面底部取样，**只取色相**（S 固定 46%、L 固定 36%）给玻璃染色 | 低：切歌/seek 后截一帧算一次并缓存 |
| **L3 真模糊** | `backdrop blur(56px) saturate(175%) brightness(1.05)`，底色降到 `.48` | 高：依赖 libmpv render API 进自己的合成树（**已落地**，见下） |
| **L4 液态玻璃**（**默认档**，`edge`） | 在 L3 之上加边缘折射：14px 带内沿法线把背景拉开 6.5px，`full` 档再加 Fresnel 与色散 | 中：CPU 逐像素，一次性重算（**只在 HTML 里**，Rust 未做） |

L3 已定稿：控制栏是染色的渐变玻璃 + 白 18% 描边 + `BACKGROUND_BLUR 56`，窗口底部另加一层 240 高的暗角遮罩（`#0B0C10` 0 → 55%），保证 11px 小字在亮画面上仍有对比。**这套现在只在 HTML 原型里**（画布的视频帧已删），参数以 `spec.json → texture_layers.L3_real_blur` 为准。音乐模式 / 设置 / 首屏没有视频底，不适用。

> 代码侧已按 L3 实现（2026-10-18 第十五轮，`--wid` 叠加窗换成 mpv 软件渲染 → GPUI 纹理）：模糊底是**同一帧降到 48×20 再拉伸**（GPU 双线性 ≈ 大半径 box blur），不是逐像素的高斯核；底色仍是 72% 平铺 + L1 渐变。观感接近 HTML 原型，大块纯色边界会略软一点。

（注意区分两种「描边」：胶囊**内部**那圈白 14–18% 是玻璃的厚度感，保留；**窗口外缘**那圈已经删掉，见下节。）

## L4 液态玻璃（默认档）

iOS 26 Liquid Glass 那一路：玻璃的边不是「更狠的模糊」，是**斜边**——边缘带的像素被沿法线往外拉开几 px，中心零位移，所以字还是清的。参数与推导见 `spec.json → texture_layers.L4_liquid_glass`，对照图 `../docs/liquid-glass.png`（胶囊）与 `../docs/liquid-glass-panels.png`（面板）。

**三块面一起上**：控制胶囊、视频信息 OSD、播放列表。三者共用同一套 SDF + 位移 + 双模糊，差别只在**极性**：

| 面 | 极性 | 底子怎么给 |
|---|---|---|
| 控制胶囊 / 视频信息 | 暗 | 自适应**压暗**：底越亮压得越狠（`scrim = .42 + .85·(meanL-.30)`，上限 .72），另有 0.45×scrim 的平铺底把顶部 11px 正文托住 |
| 播放列表 | 浅 | 反过来**铺奶白**：体部 .87（底越暗铺得越实，上限 .94），**边圈收到 .93**——浅底的边圈不能减薄，一薄就把深色画面透出来，看着像没擦干净的一圈灰 |

四条不能碰的线：

1. **位移只在边缘带**（14px，歌单 18px），中心不揉——否则 11px 时间码先糊；
2. 采样源**先模糊**，否则视频的亮部会被拉成拉丝；
3. 位移有硬上限（6.5px，歌单 7；比 iOS 的 8 保守）：压在视频上比压在壁纸上激进得多；
4. **体部和边圈两档模糊**（30px / 7px）。只用一档必然二选一：要么整块变清像换了材质，要么整块糊到没东西可弯。真实玻璃的边是斜的、看过去通透，就这条。

三个实现坑（都在 HTML 里踩过）：

- **canvas 是替换元素**：只给 `inset:0` 不管用，`width:auto` 会退回属性里的 intrinsic 尺寸（1516×180），按 2 倍铺到面板外面。必须显式 `width/height:100%`。
- **canvas 不透明**：它会把元素自己的 `background` 整块盖掉，所以「染色 + 自适应压暗」必须搬到 canvas **上面**的伪元素（`::before`），留在 `.capsule` 上等于没写。
- **位置不能靠 `offsetLeft`**：那只对居中的胶囊成立。面板是 `right:24` 对齐的，一律改用「相对窗口的 `getBoundingClientRect` ÷ 当前缩放比」，居中 / 贴边 / `fit()` 缩过三种情况同一个公式。

层序固定为：`z0` canvas → `z1` 染色+压暗 → `z2` 内容 → `z3` 1px 顶亮/底暗。

> 还没做的事：位移目前吃一张静态底（`--still`）。真机上画面在动，得每帧重算或按脏区重算——这正是它「先放 HTML 里评估，不进 Rust」的原因。成本参考：三块面全开 ≈ 27 万像素 / 46ms（Chrome，2x buffer），只在开合面板时算一次。

## 窗口边缘：不画描边

窗口自身**不画任何 1px 内描边**，画布现存 10 个帧的 `strokes` 已全部清空（`spec.json` → `window_edge.stroke = null`）。

理由：一圈亮线会把画面「封」在框里，看着像一张贴在背景上的图；去掉之后画面直通窗口边缘，只靠投影把窗口**托起来**，悬浮感才成立。这和 iina 的口径一致——macOS 上它是 `fullSizeContentView` + `titlebarAppearsTransparent`，圆角和窗口阴影都交给系统，自己一条边框都不画。

代价是浅底窗口（`#EFF1F5`）压在接近白的台面上时边缘会偏软。这是**呈现问题不是设计问题**：实际桌面壁纸不会那么浅，`docs/design-overview.png` 因此用 `#F5F6FA` 当台面。**不要为了「看得清」把描边加回来**——真觉得糊就给投影加一层贴近边缘的 contact shadow。

## 控制层闲置淡出

视频**在播**、并且 2.5s 没有鼠标/键盘输入时，标题带（含窗口按钮）、控制胶囊、底部暗角遮罩**一起退场**，画面整块让出来（`spec.json` → `chrome_auto_hide`）。

两条动作是分开做的，因为它们不是同一种东西：

| 谁 | 怎么退 | 为什么 |
|---|---|---|
| 标题带 | 向上收走：`translateY(-12px)` + 淡出，`.36s cubic-bezier(.22,.78,.28,1)`；窗口按钮 `-7px` | 它是**信息**。不做「滑出窗口」：标题贴顶边 25px，要滑 25px 以上才消失，位移太大像抽屉，而且文字会在窗口边缘被切一半 |
| 顶部压暗 | `.42s` 一并淡掉 | 它本来只为托住标题，标题走了就没有存在理由 |
| 控制胶囊 | **散成尘**：本体 `.18s` 淡出，形体交给 400 颗粒子（13px 轮廓带取点，沿 **+X** 推开 48px，640ms） | 它是**材质**。鸿蒙「沉浸光感」那条：材质不是淡出，是蒸发；光尘用加色混合 |
| 回场 | 粒子先用 520ms 聚回来，胶囊延后 `.07s` 淡入 | 聚是"响应"，不该让用户等；且必须在淡入完成前成形，否则像被擦掉而不是凝起来 |

**「从左至右」靠延迟建立，不靠位移。** 延迟 = `0.55 × x 归一化 + 0.07 × 贴边权重 + 随机`：左边先散、右边最后，一道锋面扫过去。只把位移改成 +X 而不动延迟，看到的是整块往右平移，没有"扫过"的过程。

三档方向并存，`?dustflow=` 或工具条第二排切：

| 档 | 起点 | 位移 | 观感 |
|---|---|---|---|
| **front 锋面**（默认） | 13px 轮廓带 | +X 48px | 轮廓从左往右依次蒸发 |
| side 横流 | 整个胶囊面 | +X 70~340px | 整块材质被抽走 |
| out 四周散 | 轮廓带 | 沿法线外推 | 上一版，留作对照 |

> 一条踩过的线：**带宽不能随 x 变**。想让"迎风面整列被剥"，把左端带宽放大到 3×——但那样同时把左端采样密度抬到 45%、右端只剩 9%，结果左浓右淡，读成"一团浓雾向右淡去"。方向只该由时间差表达，每列的粒子数必须一样。

- **不淡的情况**：暂停中、歌单/信息卡/拖放提示/状态胶囊开着、正在拖进度条——那会儿用户正在读东西。
- 不只是"画成透明"：淡到 `alpha ≤ 0.01` 时窗口区域也跟着放开（`chrome_rects()` 返回空），否则会留下**看不见但点得到**的按钮，同时画面少一块能双击全屏的地方。
- `prefers-reduced-motion` 下不画粒子、不做位移，只留淡出。
- 对照图 `../docs/chrome-fade.png`（稳态）、`../docs/chrome-dissolve.png`（三档方向 + 锋面相位进程）；交互看 `preview/index.html?idle=1`（冻结该状态，`&dust=0..1` 再冻粒子相位）。
- 三个诊断参数：`&seed=<n>` 固定粒子种子（静态图看不出运动方向，只有同一批粒子跨相位的位置差能说明问题；固定后同相位两次截图逐字节一致）、`&dusthold=1` 胶囊停半透明（否则粒子浮在背景上，看不出从哪块形体散的）、`&dustflow=front|side|out`。

> 粒子在 Rust 里**烘进液态玻璃那张贴图**（见 `spec.json → chrome_auto_hide.motion.rust_landing`）：
> 加光在 GPUI 的层叠里没有逐节点入口，在 BGRA 里就是逐像素加法；两者时间上不重叠，
> 一张贴图分时复用。340 个绘制节点那条路走不通，预生成帧序列也别做（几何一变全废）。

## HTML 原型

`preview/index.html` —— 单文件、**无外部依赖**（视频静帧 `assets/video-still.jpg` 与应用图标都已 base64 内联，326KB），
可以直接双击打开，也可以单独发给别人。**默认档位 = L3 + 边缘折射**（工具条第二排第一格是「+边缘折射 · 默认」）。

> 它现在**也是视频播放态的唯一来源**：主窗、播放列表展开、视频信息 OSD 这三态在画布上已经没有了（原因见上文「为什么视频态不在画布上」）。改这三态的任何东西只改这里，不用再同步画布。

- 交互：进度条点击/拖拽改时间、音量条拖拽、播放/暂停切换、ⓘ 与列表键开合面板。
- 底部工具条是**逐层叠加**的质感档位，也可用 URL 参数固定：
  `?layers=`（L0 设计稿原样）· `?layers=enh`（L1 方向光）· `?layers=enh,tint`（L2 画面染色）· `?layers=enh,tint,realblur`（L3 真模糊，默认）· `?layers=noblur`（Win 现状）
  另有 `&panel=osd|playlist`。四层的具体数值见 `spec.json` 的 `texture_layers`。
- 液态玻璃另有一组开关：`&liquid=edge|full`（**默认 `edge`**，`&liquid=off` 才关），配套两个诊断参数 `&card=1`（换成高频测试卡：竖线看水平位移、网格看圆角法线是否连续）、`&glassdbg=1`（只画位移场：白=贴边 maxd → 黑=带内沿 0）。
- 截图参数：`?idle=1` 冻结在闲置淡出态（加 `&dust=0.42` 再冻结粒子相位）、`?bare=1` 去掉页面留白和底部工具条（截图区域正好是 1280×800 的窗口本身，不用再按坐标裁；顺带关掉过渡，避免截到半透明中间态）。
- 列表 10 条与设计稿 `21:170` **逐字一致**（标题 / 元信息 / 当前播放行的三柱图标 / 底部「10 个文件 · 3:42:18」）。HTML 里的列表数据在脚本开头的 `items` 数组，改数据只改那里。
- 换底图：改 `assets/video-still.jpg` 后要重新内联进 HTML（相对路径在预览面板里会被 403）。

### HTML 是「验收基准」，不是「实现来源」

- **数值**以 `spec.json` 为准（含 `texture_layers` 四层的精确参数）；HTML 里能读到同名参数，但不要从 CSS 里抄。
- **视觉**用 HTML 当对照：实现完截个图，和 `?layers=...` 的对应档位比。
- HTML 里这些**没有对应实现**，别照搬：`backdrop-filter`（GPUI 无）、`transform`/`scale`（gpui-pre 0.3.9 没有，胶囊淡出只沉 3px、没有 `.985` 缩放）、加色混合（贴图只能 source-over，粒子用「往白推」近似）、字体度量、以及拖拽吸附。

## 更新流程

1. 在**设计画布会话**里说「重新导出 design/」——会重跑导出并更新 `spec.json`。
2. 导出物**不要直接落到 `frames/`**：`export_nodes` 的留白随阴影半径变、而且阴影像素会被算进内容边界。先下一份原始图，再跑
   `python scripts/normalize-frames.py <原始图目录>`（按 `spec.json` 的节点 id 找文件，用 `alpha≥250` 定位窗口矩形、按设计尺寸×2 裁、透明区 RGB 清零），
   最后 `python scripts/make-overview.py` 重拼总览图。
3. 检查 `git diff design/`（图片会全部显示为二进制变更，属正常）。
4. 若 `spec.json` 里 `meta.exported_at` 变了但数值没变，说明只是重导出，可以不改代码。

**不要**在开发会话里试图读取 Ardot 链接：那组设计工具不在开发会话里，这是宿主按会话注入的，没有配置开关。

## 已知偏差（量图前必读）

- 帧已裁到窗口内容：**图像 = 设计尺寸 ×2**，可直接除 2 量坐标；窗口四角是透明圆角（radius 10），**窗口外缘没有描边**，边缘只有投影渐隐（见「窗口边缘」）。
- **`frames/` 里没有 1280×800 的帧了**（视频播放态已删）。画布上对应位置是一块「占位 · 视频播放态」说明板，看到它别当成界面。
- 闲置淡出没有独立的设计帧：它是瞬时状态，静态帧表达不出过渡。稳态看 `../docs/chrome-fade.png`，消散相位看 `../docs/chrome-dissolve.png`，实际动效只能开 `preview/index.html`。
- 静态导出画不出真模糊。L3 在 PNG 里只表现为一块**均匀染色玻璃**（染色的色相是从当前素材那一帧算出来的固定值 `rgb(50,103,134)`）。看真效果开 `preview/index.html`；进代码后必须运行时取样，换片重算。
- `../docs/capsule-compare.png` 是历史对照图：它的「画布 L3」那一半取自已删除的视频帧，**无法重生成**，别拿它当现状。
- 背景是**透明**的；某些查看器会把透明区的 RGB 残余显示成绿色（预览工具里见过），实际 alpha=0，不是设计元素。
- Win 设置窗以 `21:807`（960×720，含标题带）为准；画布上还留着一个旧版 `2:406`（960×680 无标题带），**不要用**。
- OSD 里的分辨率/码率/色彩是设计稿示例值，代码应取 mpv 实际值；`video-bitrate` 不可用时显示 `—`，不要补假数。
- `assets/chroma.png` / `assets/chroma.ico` 已按 Logo C 重建（`scripts/make-icon.py`：16 倍超采样、9 档尺寸逐档重画、不烤投影）。16px 也用同一图形等比缩——画布上的方块探索稿 `2:528` 实测更难认，**不要**拿它做 ico。
